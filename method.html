Method

How a case is tagged

Each case is tagged independently on the two classification axes, with Module 3 observations attached wherever the documentary record supports them.

Scope

What this method can and cannot see

The framework applies to regulatory orders that national or international authorities currently form or operate through documented rules, formal classifications, and administratively recognizable decisions.

Tracing is confined to the documentary record: published rules, official gazettes, consultation records, court filings, and industry comments. Exchanges that never entered that record are out of reach. This does not mean such paths don't exist, only that this method cannot see them.

Consequence for the data

Because the scope claim is documentary, every numeric value in a case file carries a source reference into that case's own source list. A number without a citation is rejected at validation rather than published with an asterisk.

Template 4b

The two kinds of blank

Most fields in a filled case file are empty. Two different facts produce that emptiness, and collapsing them loses information the framework depends on.

  • Not documentednull

    The field applies to this case, but the documentary record does not settle it. Renders as not documented.

  • Not applicablenot_applicable

    The branch never reaches this question. Currently produced only by Event Type = Enactment, which exits at Step 1 of 2.1. Renders as an em dash.

    An Enactment case has no collision points and no timeline markers. That is the branch working correctly, not a gap in the research.

Worked example · a staged normalization

The Anthropic export-control shutdown records time-to-response at roughly zero days, models pulled immediately and worldwide. Normalization was staged: vetted organizations first, the public model days later, broader release of the more capable model held longer. Each stage is recorded separately rather than collapsed to one number, so the schema stores this field as a list even when only one stage is known.

Constraints

What the validator will not let you do

  • Correlate the two axesnon-rule N1

    No validation rule may make a Module 1 field depend on a Module 2 field, or the reverse. A validator that enforced a correlation between them would re-impose the tree v3 removed.

    If a correlation appears in the data, that is a finding, not a constraint.
  • Add a score to Module 1 or 2non-rule N2

    Modules 1 and 2 carry no numeric fields, and none may be added.

  • Publish an uncited numberrule R4

    Any non-null quantitative value must carry a source id present in the case's source list.

  • Invent a tagrule R7

    Every enum value must appear in the schema file. An unrecognised tag does not announce itself — it silently splits a category in two wherever cases are grouped, and shows up only as a listing that looks slightly wrong.
