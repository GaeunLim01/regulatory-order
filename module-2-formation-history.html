This module is built by tracing the documentary record backward — for example, U.S. BIS computing and semiconductor export-control rules from 2009 through the 2026 Remote Access Security Act — to find structural features in how the boundary was set or reset.

2.1

How the rule changed

Event Type. This is not a flat three-way classification. It is a two-step branch, and the earlier three-column layout obscured that hierarchy.

Step 1 — Is there a prior state to compare against?
  • No → New rule from scratch (Enactment) Obligations arise whole. No accumulated cases yet, so Step 2 and the Formation Trace questions below do not apply. exits here
  • Yes → go to Step 2
Step 2 — Did actors collide with one another directly?
  • Yes → Reactive (Conflict)
  • No → Proactive (Amendment) No direct collision, but the amendment creates a burden for other actors later.
Reading note · v2 → v3

Earlier drafts listed Enactment, Amendment, and Conflict as three parallel columns, which made Enactment's blank cells — no collision points, no timeline markers — look like missing data. They are not missing. Enactment exits the branch at Step 1, before the questions that produce those cells even apply.

The case schema encodes this distinction directly: an Enactment case records not_applicable where a Conflict or Amendment case would record a value or a blank. A blank left by an unanswered question and a blank left by a question never asked are different facts.
