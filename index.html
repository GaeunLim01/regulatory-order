This framework did not originate as a single top-down taxonomy. It grew out of two separate lines of inquiry, plus a third layer describing what happens once order is in place. Earlier drafts nested all of it under one branching tree with Event Type at the top, which produced recurring friction: items belonging to one inquiry kept showing up as awkward children of the other. This version keeps the three modules explicitly independent.

Modules 1 and 2 answer genuinely independent questions. A given case is classified on both axes at the same time, and neither tag determines the other. Every case carries two tags, not a tag and a sub-tag.

Module 3 · A process, not a classification

Downstream

Once an order exists — regardless of whether it arose through an Instability-type collision or a Formation-History-type proactive amendment — how does it reach actors, and how are consequences distributed? This module does not classify cases. It describes a common downstream process that applies once an order exists, no matter which module produced it.
